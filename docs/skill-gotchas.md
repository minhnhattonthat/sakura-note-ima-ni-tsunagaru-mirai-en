# Skill gotchas (one line each: reference file, then the fact)

- references/emulator-qa.md §emu.py: `--mash` presses from frame 0 when a `--script` drives input with `L.press` and `--route` is empty (mash runs whenever emu.py's own route is done); it typed into a name entry. Don't combine `--mash` with a script-driven key program.
- references/emulator-qa.md §DeSmuME: without `--sav`, the QA fork reads and writes `tools/desmume/desmume-qa/Battery/<rom>.dsv`, shared by every run; a run that saves changes the next run's title/file menus. Pass a fixed `--sav` fixture for warps.
- references/emulator-qa.md §Debug tool (NDS): an exec hook on the game's archive entry-open routine that rewrites the entry id register can swap the boot script for a leftover debug script, with no ROM patch (Sakura Note: 2477 -> 2494 gave the full debug menu).
- references/emulator-qa.md §DeSmuME: after `--state-in` with JIT, menu screens stayed grey for 100+ frames even after a touch; `--debugger` rendered them at once.
- references/emulator-qa.md §Debug tool (save editor): `--mash A` through a chapter never reached a save on an adventure game with field save points; find the save-point spawn command in the map scripts (Sakura Note `SpawnSavePoint`), warp to that map with the debug menu and walk to it. Then map fields by diffing the RAM state struct (find it by searching RAM for the default names) across debug-warped chapters: one game-written save is enough.
- references/emulator-qa.md §emu.py: `--route-str` takes `frames key;frames key` (`"60 -;6 start;150 -"`), not warp-style tokens (`w60 start`); a wrong form fails only in lua_error.txt.
- SKILL.md (Claude Code, Orca worker): `Skill translate-retro-game:translate-retro-game` came back "Unknown skill" though the plugin is enabled; read `$SKILL/SKILL.md` by path (`python tools/skill.py`).
- references/pipeline.md §Extract: a `.tbl` keyed by little-endian bytes (`1000=あ` for code 0x0010) read by an ad-hoc parser with `int(key,16)` byte-swaps every code; the dump then showed `[00xx]` for the credits and the file was blamed on "another font". Decode through `tbl.py` only.
- SKILL.md §Ground rules (context-mode): a plain `cat` of a 3-5 KB file through Bash/PowerShell also comes back as a stub, not just Read; read with offset/limit or print the answer from ctx_execute.
- references/platform-nds.md §Assembling hooks: keystone fails `adr rX, label` when label is an equate (`w = 0x...`): KS_ERR_ASM_MISSINGFEATURE. Put data tables inline after the code as `.byte` lines and let `adr` reach them.
- references/pipeline.md §Marker build: a speaker-name tag can come from a separate file and a separate 8x8 font with its own fixed-step loop and a short memcpy (Sakura Note: 10 u16 copied from 2610); a marker that vanishes or stops at N chars points at that copy, not the box. Packing two 8-bit codes per u16 doubled the room with no buffer change.
- references/emulator-qa.md §DeSmuME Lua: the QA fork's Lua is 5.1: `&`, `>>` etc. are a parse error (`')' expected near '&'`); use `%` and `math.floor(x / 2^n)`. Two `--script` probes share globals, so a `--var AT=` meant for one (ramdump) breaks another that expects a table: give probe vars distinct names.
- references/pipeline.md §Checks (NDS): when arm9 grows (new autoload block), ndspy relays out NitroFS and every file moves, so `romdiff.py` over the whole ROM is useless; audit leaf by leaf (header fields, arm7, overlays, files, arm9 sections) and run romdiff per fixed binary with the write log. ndspy's `MainCodeFile.save` also rewrites 3 module-params words (autoload list start/end, at nitrocode magic - 0x1C): allow them.
- references/pipeline.md §Recon (credits): a staff roll whose line x "isn't in any data file" can be code: one call per line with `mov r1,#line; mov r2,#x; mov r3,#y` immediates (Sakura Note overlay 1, 77 calls). Found by OAM dump -> RAM search for the on-screen x -> write watch on that field -> caller chain with stack args; re-centre by rewriting the `mov r2` immediates.
- references/pipeline.md §Checks: test a line-centring idea with an unpadded QA line before adding padding: the Sakura Note text engine already centred each line within its entry's widest line, so leading-space padding double-centred.
- references/emulator-qa.md §Stress saves / Save fixtures: a fixture made through a debug warp keeps the debug script's own (Japanese) default names, not the build's, so English tours showed kana names in name placeholders (chapter cards) and reviewers flagged them; set the English default names with the save editor in the base fixture (Sakura Note `make_save.en_names`).
- references/emulator-qa.md §Visual QA (no subagents): `codex exec -s read-only -i SHEET.png ...` takes the sheets as attached images; its sandbox can't open repo files, so put the brief, the glossary names and the id order in the prompt and parse `id<TAB>verdict<TAB>note` lines out of `-o` (Sakura Note `tools/vqa_run.py`).
- references/platform-nds.md / graphics.md: NNS RECN per-cell VRAM-transfer table entries are (char offset, size); reading the size as the offset renders sprite sheets scrambled but plausible (Sakura Note pause tabs). Text over art or translucent panels in 8bpp BG bitmaps needs inpainting, not a flat clear (`tools/gfx.py` `inpaint`).
